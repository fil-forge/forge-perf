How this is measured

What runs. A single AWS m9gd instance runs every Forge service in Docker using the published main images, pinned by digest for the run. After each run the box deletes all containers, volumes, stored objects and its NVMe data, so every run starts cold.

The workload. The storage-qualification drill's import profile writes objects of about 128 MiB through the S3 gateway, reads each back within a minute and restores ranges of them. Each per-trigger run writes 100 GB; each nightly run writes up to 500 GB.

What the number means. The drill measures ingest in 30-second windows. p5 is the highest rate that at least 95 % of those windows held. The median is shown beside it. A run with fewer than 20 steady windows is marked, since its p5 is then its slowest window.

The gates. Each gate is the highest rate the named instance type can sustain: the lower of its measured S3 upload throughput and its NVMe sequential write speed. A gate lights when a valid run's p5 reaches the ceiling measured at the time of that run. A gate without a measurement is drawn dashed.

What is modeled. Storage node services and central services run on one host with a fixed 15 ms round trip added between the two groups, standing in for a storage provider's site about 15 ms from central services in us-east-2. Piri stores blobs in Amazon S3 in the same region, standing in for the provider's S3 service. The client runs on the same host as the stack with no added delay, and connections are plain HTTP/1.1 where production uses TLS and HTTP/2.

Outcomes. Runs with availability errors keep their numbers and are marked; they do not move the thermometer. Invalid measurements (the added latency drifted, an image changed mid-run, or the run stopped before its size) and failed runs are shown and excluded. Calibration runs, made while the setup is tuned, appear in the table only.
